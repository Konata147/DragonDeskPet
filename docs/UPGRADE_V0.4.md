# V0.4 升级与回退指引

当前 V0.4 仍为开发验收版，正式发布另行确认。本指引不要求现在就迁移正式版数据。

## 保留数据升级

1. 从系统托盘选择「退出」，不要只关聊天气泡；同时关闭教务导入窗口。
2. 将旧程序旁整个 `data` 文件夹复制到自己选择的备份目录，推荐 D 盘。
   保留旧版程序文件夹，不先删除或覆盖。
3. 将新版 ZIP 完整解压到一个新的 D 盘目录。不要在 ZIP 内直接运行，也不要只取 EXE。
4. 若需沿用旧数据，将旧版 `data` 的副本放到新目录的 `DragonDeskPet.exe` 旁。
   如果新目录已有测试数据，先备份并确定保留哪份；不要混合两份 JSON 文件内容。
5. 确认旧版已退出，再启动新目录的 EXE。检查自己的设置、清单和课表。

由于单实例保护，旧程序未退出时点击新版可能只唤醒旧程序，而不是启动新版。
当前项目的独立 V0.4 验收目录已有测试课表，不应在未确认前覆盖其 `data`。

## 数据格式与密钥

- V0.4 兼容读取旧效率数据，首次保存新格式前保留
  `data/productivity.json.pre-v0.4.bak`；已有此备份时不覆盖它。
- 这个文件只备份效率 JSON，不等于完整 `data` 备份，因此仍建议执行上面的手动备份。
- 保持旧固定时间课程的行为；只有使用节次时间模式的课程才随冬夏配置计算钟点。
- API Key 按 Windows 当前用户加密。换电脑或换 Windows 用户时不要假定能直接解密，
  可能需要重新配置 Key；不要为了迁移把 Key 改成明文或上传设置文件。
- 备份含个人课程、提醒等内容，不要把 `data`、课表原文件、登录缓存提交到公共仓库。

## 需要回退时

1. 退出新版，另外保存新版 `data`，以免丢失升级后新增的课程或事项。
2. 使用保留的旧版程序，以及升级前备份的旧 `data`。
3. 不要让旧版直接保存已加入 V0.4 调课、冬夏节次和导入快照的新数据；
   旧版不理解这些字段，可能丢失新功能信息。

回退到旧备份意味着升级后的新增数据不会自动出现在旧版里。请先比较、再决定，
不要删除唯一副本。本指引不会自动移动、替换或删除任何文件。

## 开发者打包注意

- 发布包从干净的构建输出生成，不从已运行且含 `data` 的文件夹直接压缩。
- 包中应有角色资源、程序图标、本地 OCR 模型、原生依赖和第三方许可。
- 原始参考图、私人课表、运行数据、浏览会话、密钥和日志不应进入分发包。
- 发布脚本 `-Force` 会删除旧输出，不能用于含有用户数据的运行目录。
- 发布前核对版本、SHA-256、自动测试及远程 CI；正式版本号和 GitHub 发布须经确认。
